stonewang_daytrade_1.2.0

Released: 2026-07-29
Based on: stonewang_daytrade_1.2

1.2.0 changes (7/29):

Backtest slippage models (4 models added):
- Entry slippage: pullback × (1 + SLIPPAGE_ENTRY_PCT=0.5%) → market buy fills at ask, not bar low
- Exit slippage: stop × (1-2%), target × (1-0.3%), trailing × (1-1%), force close × (1-1%)
- Re-entry slippage: reentry_price × (1 + SLIPPAGE_ENTRY_PCT=0.5%)
- Re-entry exit slippage: reentry stop × (1-2.5%), reentry trailing × (1-1%), reentry force close × (1-1%)
- All slippage params from config (SLIPPAGE_STOP_PCT, SLIPPAGE_TARGET_PCT, etc.)
- Trigger conditions unchanged (raw prices), only execution prices adjusted
- Slippage disabled by setting params to 0

MIN_RETRACE_PCT threshold added to build_trade_plan:
- Forces capped mode when (open - entry) / entry < 3%
- Matches live trading calc_targets behavior

Capital deployment optimization:
- EQUITY_POSITION_RATIO: 0.80 → 1.0 (100% capital deployment)
- Slot-based allocation: remaining_slots = MAX_POSITIONS_PER_DAY - active_positions
  (instead of len(candidates) - len(entry_checked))
  → consistent $100/stock regardless of candidate count
- MIN_POSITION_SIZE: $85 → $40 (allows more stocks to enter)
- REENTRY_MIN_POSITION_SIZE: $40 → $20
- Backtest pos_per_stock = equity × ratio / max_positions (matches live slot logic)

Backtest re-entry improvements:
- Re-entry cutoff time check (12:30 EST)
- REENTRY_MIN_POSITION_SIZE check
- Entry slippage applied to re-entry price (reentry_price_actual)

Chain robustness fixes (inherited from 1.2):
- P0: force_sell_position intent parameter — partial ladder sells NEVER use close_position
- P1: _wait_cancel_confirmed() at 6 critical cancel→action nodes
- P2: Batch order status cache (_order_cache)
- P3: Polling interval reduced from 5s to 3s

OCO ladder sell system (inherited from 1.2):
- OCO_ENABLED=True for T2+ pre-placed orders
- Eliminates 5-second polling delay between tiers
- OCO stop buffer = trail_pct (progressive: 2%/2.5%/3%/3.5%/4%/5%)
